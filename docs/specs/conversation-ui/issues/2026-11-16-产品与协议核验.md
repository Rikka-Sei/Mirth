**最后更新:** 2026-11-16

**关联章节:** 六域规格 §1.0、§4、§6、§7；以会话交互域承接完整产品能力核验登记
**关联决策 ID:** 未归因（open）

## 1. 现象

本规格定义目标行为与可验收界面结果；当前工作没有完成 Cinny 全功能逐项盘点、Matrix homeserver 互操作验证、加密/设备恢复协议验证、通话 provider 验证或真实服务端性能测量。不能将草案中的行为或 Demo 展示当成已有产品能力或 Matrix 全功能兼容证明。

## 2. 证据链

| 证据 | 位置 |
|---|---|
| 产品能力边界与问题清单 | `docs/specs/README.md`、各域规格与 `docs/research/技术选型与界面设计.md` |
| Matrix 协议及 SDK 行为尚未逐项映射到所选 SDK 版本 | 需对照正式 Matrix Client-Server API、matrix-js-sdk 文档及目标服务器验证；当前未形成证据记录 |
| 真实延迟、可靠性、容量数值尚未测量 | Demo 仅本地示例数据，不产生可代表目标部署的测量 |

## 3. 根因

待确认。规格定稿前需要逐条闭合协议/SDK能力及服务端差异；当前将这些事项保留为 open，避免把假设写成事实。

## 4. 影响

产品目标路径仍可作为 Draft 验收目标；生产兼容性、恢复/加密正确性、通话可用性和量化 NFR 不能被视为已证实。用户不得据此把应用发布或宣称具备完整 Cinny 能力。

## 5. 建议

- 协议与 SDK：针对指定 matrix-js-sdk 版本和 homeserver 建立需求—API 映射，核验认证、同步、加密、设备验证、恢复、媒体、通话边界。
- 性能：在目标设备、网络、数据规模与服务端环境明确后测量并确认 §6 拟议阈值。
- 产品覆盖：以 Cinny 明确版本的可观察用户能力为比较清单，逐项标记满足、缺失、差异或不适用；未闭合项不得在正文宣称已实现。
- 若核验推翻设计图中的行为，先更新图及 §9 决策归因，再修改需求与投影。

## 6. 闭环记录

- open：等待对目标 SDK/服务端矩阵、Cinny 对标清单、恢复/通话能力边界及 NFR 实测结果的核验。
