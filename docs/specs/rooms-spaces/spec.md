# 房间与空间规格

**状态:** Draft。目标行为提案，未核验具体 Matrix API、SDK 签名或实现；不构成 authoritative 规格。
**版本:** 0.2（D04 修正敲门后继）
**受众:** 产品、客户端工程、测试与评审。
**范围:** 房间与空间发现、创建与参与、邀请/敲门、成员管理、资料/权限、空间层级、升级、离开及浏览授权。
**治理:** 行为由本文件定义为提案；协议细节待核验，不以 Demo 或空屏障证明完整性。
**变更历史:** 从聚合稿按用户要求拆出，原稿见[历史材料](../message-delivery/history/2026-11-16-拆分前聚合稿.md)；调查见[证据索引](../../research/客户端核心规格调查.md)。

## 1. 背景与目标

### 1.0 设计图景

```text
用户查找联系人、创建私聊、房间或空间
|-- 目录/联系人可读 -> 展示匹配结果，用户选择已有私聊或新建目标
|   |-- 已有可访问私聊 -> 打开该会话；本次选择结束
|   +-- 创建获服务端确认 -> 展示新对象并交给导航打开
|-- 搜索/创建拒绝或失败 -> 保留输入并显示原因；用户重试或返回
+-- 用户取消 -> 不提交新的创建操作；已确认创建的对象不被假称撤销

用户从链接、邀请或目录选择房间
|-- 已加入且可访问 -> 打开房间并请求时间线；本次进入结束
|-- 收到有效邀请 -> 展示来源及接受/拒绝/取消
|   |-- 接受且服务端确认 -> 更新房间成员身份，打开房间
|   |-- 拒绝且服务端确认 -> 更新邀请状态，保持未加入
|   +-- 请求失败或取消 -> 保留实际确认状态与邀请，显示原因；可重试或返回
|-- 未加入但房间允许加入 -> 用户确认加入
|   |-- 服务端确认 -> 更新成员身份，打开房间
|   +-- 拒绝/请求失败 -> 保持未加入，显示原因；可重试或返回
+-- 不存在、不可见或禁止访问 -> 仅显示服务端允许的原因，不泄露不可见内容；返回或结束

用户浏览空间目录或空间层级
|-- 服务端允许读取空间 -> 展示获准的空间资料与子项（成员与否不单独否决浏览）
|   |-- 选择子空间 -> 按空间读取权继续浏览
|   +-- 选择房间 -> 依据该房间独立可见性与成员状态打开、加入或提示限制
+-- 拒绝访问/加载失败 -> 不展示未授权内容，区分拒绝与失败；重试或返回

用户敲门请求进入受限房间
|-- 请求提交成功 -> 显示待处理状态；等待房间管理结果
|   |-- 收到邀请 -> 按上面的邀请接受/拒绝路径处理；邀请本身不是加入
|   |-- 服务端同步确认已加入 -> 更新成员状态并打开房间
|   +-- 收到拒绝或用户撤回获确认 -> 保持未加入并显示结果；用户可重新发起（若允许）
+-- 请求失败或用户取消 -> 不显示已敲门；保留既有成员状态并可重试/返回

用户在房间/空间资料页管理资料、成员、权限、加入规则、地址或层级
|-- 当前权限有效且输入可提交 -> 提交所选变更
|   |-- 服务端确认 -> 更新确认资料/权限；后续操作重新按新能力判断
|   +-- 拒绝、权限变化或请求失败 -> 保留已确认状态与未保存表单，显示原因；重试或取消
+-- 无权限、输入无效或用户取消 -> 不提交变更，保留服务端确认状态

用户升级房间
|-- 显示旧房间与目标升级影响并确认
|   |-- 服务端确认升级与后继房间 -> 展示旧/新房间关联和可进入的新房间
|   +-- 拒绝、失败或响应未确认 -> 不伪造升级完成，保留旧房间入口及可恢复状态
+-- 用户取消 -> 不提交升级；本次操作终止

用户离开房间或空间
|-- 用户确认离开所选对象 -> 只提交该对象的离开操作
|   |-- 服务端确认 -> 更新该对象成员状态并返回可访问列表
|   +-- 拒绝或请求失败 -> 保留最后确认成员状态并显示原因
+-- 用户取消 -> 不变更成员关系；离开空间不自动离开其子房间
```

此图为作者提案；房间与空间的读取授权分别由服务端事实裁决，不将空间成员关系推导为子房间成员关系。

### 1.1 背景

房间承载对话与成员权限，空间组织房间/子空间。目录调查指出层级可多父、非严格树，且非成员浏览须由服务端可见性裁决。Cinny 基线含邀请、敲门、成员/权限管理、地址、层级与房间升级；不能因精简删除。

### 1.2 目标

- D01：保留房间参与和空间管理相关的功能下限，并明确成员与可见性分离。
- D02：房间成员状态、空间关系与权限确认由房间/空间服务分别拥有。
- D03：图中操作结果是提案；API 映射与升级语义待核验。

### 1.3 非目标

- 本域不拥有账户身份/密钥；身份由 [session-security](../session-security/spec.md) 提供。
- 本域不拥有消息编辑器、时间线历史或发送事务；发送引用[消息发送](../message-delivery/spec.md)。
- 不将空间建模为单父树，不强制拒绝所有非成员浏览空间。

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 房间 | 独立的会话对象，有自己的可见性、成员状态与权限 |
| 空间 | 组织房间或子空间的层级对象；与房间成员关系分离 |
| 可见性 | 服务端允许当前身份读取对象资料或内容的事实，不等同成员身份 |
| 成员状态 | 用户在特定房间/空间中的服务端确认关系 |
| 敲门 | 对受限房间提交待审批的加入请求 |
| 升级 | 由服务端确认的房间替代/关联操作；具体协议细节待核验 |

## 3. 系统模型与状态机

### 3.1 架构与边界

```text
会话/安全域 --账户身份--> 房间空间协调器 <--用户意图-- 房间与空间视图
                                    |--加入/邀请/敲门/管理--> 协议适配边界 --> 服务端
                                    |--成员、可见性、层级确认--> 列表/导航/详情
                                    +--权限与房间上下文--> conversation-ui、message-delivery
```

组件责任：

| 组件 | 输入 | 意图/责任 | 状态所有者 | 失败与接收方 |
|---|---|---|---|---|
| 发现/目录视图 | 搜索或目录范围、服务端允许资料 | 发现空间/房间并选择目标 | 发现服务拥有确认结果 | 区分空结果、拒绝、加载失败并反馈视图 |
| 邀请/加入流程 | 邀请、目标房间、用户选择 | 接受、拒绝、加入或取消 | 房间参与服务拥有确认成员关系 | 失败保持原状态，返回入口 |
| 敲门流程 | 受限房间、权限结果 | 提交并追踪待审批加入请求 | 房间参与服务拥有请求状态 | 邀请交回接受/拒绝入口；确认加入才更新成员；失败不假称提交成功 |
| 空间导航 | 获准空间与子项 | 展开、选择空间/房间 | 空间目录服务拥有关系；列表拥有临时选择 | 拒绝/失败不泄露新内容，返回/重试 |
| 管理面板 | 当前权限、资料、成员与表单 | 修改资料、权限、规则、地址、层级 | 服务端确认值归房间/空间服务；表单持有编辑 | 失败保留旧确认值及未保存表单 |
| 升级流程 | 当前房间、影响说明与确认 | 提交房间升级 | 房间服务拥有升级确认及关联 | 未确认保留旧入口，结果交回视图 |
| 离开流程 | 明确选择对象与影响范围 | 离开单一房间或空间 | 对应成员服务 | 失败保持原状态；不得扩展到子房间 |
| 协议适配边界 | 目标操作及身份 | 映射已核验协议请求 | 不裁决 UI | 错误映射待核验，交还发起流程 |

### 3.2 状态定义

房间读取状态、房间成员状态、空间读取状态、空间成员状态、邀请/敲门请求、管理确认值是彼此独立的概念状态。层级关系允许服务端提供的多父关系；图不主张特定数据结构。

### 3.3 转换与可执行语义

本域没有有限事件模型。具体协议与操作的可执行语义待具体协议抽象及证据调查后定义；不新增 Haskell 模型凑形式，不声称 G7 通过。未来抽象必须保留图中服务端确认、拒绝、失败与用户取消的后继。

### 3.4 外部输入域矩阵

| 输入 | 成功观察 | 失败/取消后继 | 接收方 |
|---|---|---|---|
| 可见性/目录结果 | 展示服务端允许的房间或空间资料 | 拒绝与加载失败分别提示 | 发现/空间视图 |
| 邀请/加入响应 | 仅确认后更新成员状态 | 保持未加入/原邀请状态 | 房间参与流程 |
| 敲门后续 | 邀请转交接受/拒绝；确认加入后打开 | 拒绝或撤回确认后结束待处理 | 房间参与流程 |
| 管理变更响应 | 确认后更新资料/权限视图 | 保留最后确认状态 | 管理面板与后续能力判断 |
| 升级/离开响应 | 确认后更新目标对象状态 | 不伪造结果、不扩大范围 | 房间/空间视图 |

## 4. 功能需求与接口契约

具体 API/SDK 签名未核验，不定义 code facts。

- **REQ-001 房间发现与参与（P0，D01/D03）**：作为寻找会话的用户，我需要区分发现、创建、邀请与加入，以免向错误对象操作。Given 可访问房间、联系人或有效邀请，When 用户选择创建、加入、接受或拒绝，Then 只在服务端确认后更新对象与成员/邀请状态；失败或取消保持已确认状态且不启用成员专属操作。
- **REQ-002 空间层级与浏览（P0，D01/D02）**：作为浏览空间的用户，我需要按对象授权浏览，以免把组织关系误当访问权。Given 服务端允许读取某空间，When 非成员用户浏览，Then 展示授权资料及子项；选择房间时再独立检查该房间可见性/成员状态。空间成员不推导子房间成员，非成员身份本身不构成拒绝浏览空间的理由。
- **REQ-003 管理、敲门、升级与离开（P0，D01/D03/D04）**：作为管理或加入房间的用户，我需要分别观察请求与成员结果，以免将待批准当作加入。Given 服务端能力与权限允许，When 用户敲门后收到邀请，Then 回到接受/拒绝邀请流程，不自动显示已加入；管理、升级、离开只按对应对象及服务端确认更新；失败/取消不得假称成功，离开空间不自动离开子房间。

## 5. 错误模型

目标分类，不是已核验错误码：不可见/不存在（仅展示可公开原因）、未授权、成员权限变化、请求拒绝、网络失败、敲门拒绝/撤回、管理输入无效、升级结果未确认、用户取消。保留最后确认状态；未确认响应不得作为成功。具体协议错误映射待调查。敲门参考 [Matrix 敲门](https://spec.matrix.org/v1.19/client-server-api/#knocking-on-rooms)；不假设所有服务器提供请求到期事件。

## 6. 非功能需求（NFR）

不提出无依据数值。授权内容按服务端可见性边界呈现；不根据空间成员身份推导子房间访问，不泄露不可见房间详情。缓存或旧目录结果不能覆盖新的拒绝结果，具体一致性策略待协议抽象核验。

## 7. 异常与边界条件

| 场景 | 目标结果 |
|---|---|
| 非成员空间浏览且服务端允许 | 可以浏览获准内容，不因非成员身份自动拒绝 |
| 空间可见但子房间不可见 | 不暴露该房间未授权资料；不影响空间其他可见项 |
| 空间成员但未加入子房间 | 房间页按房间自身成员状态处理 |
| 多父级空间关系 | 不假设唯一父级或严格树 |
| 升级响应丢失 | 保留旧房间入口并标记结果未确认，不伪称完成 |
| 离开空间 | 不扩展为离开所有子房间 |

## 8. 验收标准

- 加入、邀请接受/拒绝、敲门后收到邀请/加入确认/拒绝/失败/取消均有独立结果证据；未核验服务端策略不得伪造服务端能力。
- 可见空间的非成员浏览、空间成员与子房间成员不相等、子房间不可见三类情况分别验证。
- 管理、升级及离开操作只在服务端确认后更新视图；失败保留最后确认状态。
- 保留 Cinny 基线中的成员管理、权限、升级、地址、加入规则与空间层级能力；源码定位不等于功能完整验证。
- 本域保持 Draft，直至协议映射、实现行为与测试证据经核验；不声称 authoritative。
