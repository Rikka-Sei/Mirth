# 房间与空间操作协议映射待核验 — Issue

**状态:** open
**发现日期:** 2026-11-16
**最后更新:** 2026-11-16
**来源:** 规格拆分与调查报告
**关联章节:** [spec §1](../spec.md#1-背景与目标)、[REQ-001–003](../spec.md#4-功能需求与接口契约)
**关联决策 ID:** 未归因

## 1. 现象

目标规格保留发现、邀请/加入/敲门、空间层级、成员管理、权限、资料、地址、升级与离开，但具体 API/SDK 映射、服务端能力限制及失败响应尚未逐项核验。

## 2. 证据链

| 证据 | 位置 |
|---|---|
| 调查报告列出房间生命周期、Space 多父层级、权限与受限加入；源码定位不代表完整支持 | [调查报告](../../../research/客户端核心规格调查.md) §§协议能力表与 Cinny 源码调查 |
| 用户明确的拆分约定要求空间成员与子房间成员分开，非成员浏览按服务端可见性裁决 | 本次任务约定 |

## 3. 根因

能力目录和 UI 源码线索没有替代具体 SDK 版本、请求结果与可见性策略的协议核验。本 issue 不认定任何未核验 API 已存在。

## 4. 影响

目标行为可用于后续调查，不能据此声称实际支持完整房间/空间流程；规格保持 Draft。不得以非成员身份一概拒绝浏览空间。

## 5. 建议

按操作和服务端确认结果逐项核验协议及目标实现，并验证多父关系、子房间独立成员状态、敲门、升级与失败后继；保持功能下限。
