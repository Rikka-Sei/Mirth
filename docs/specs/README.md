# Mirth 规格入口

按行为和状态所有权分为六份。**均为产品目标 Draft**；操作图、模型与源码证据分别验证，不将示例数据 Demo 当作 Matrix 功能实现。用户已确认的进入会话—阅读—回复—发送路径分配到相应域；其他流程和数值仍待审阅。

| 规格 | 唯一负责的契约 | 不重复定义 |
|---|---|---|
| [账户与安全](session-security/spec.md) | 发现/认证、账户与设备会话、信任验证、密钥恢复与备份 | 不定义发送重试或房间成员规则 |
| [房间与空间](rooms-spaces/spec.md) | 目录、邀请/敲门/加入/离开、成员与权限、空间层级和管理 | 不把 Space 成员等同子房间成员，不定义编辑器 |
| [会话交互](conversation-ui/spec.md) | 导航与响应式、阅读与回执、普通草稿、独立编辑草稿、关系/线程、媒体查看和图片包 | 关系操作直接使用 SDK；仅普通新消息交给消息发送域 |
| [消息发送](message-delivery/spec.md) | 普通新消息快照、事务、准备/提交、重试/取消、未知结果与回显合并、内容恢复 | 不接管编辑/反应/撤回/置顶，不重新规定认证或房间加入 |
| [通话](calling/spec.md) | 来电、权限、接听/拒绝/忽略、活动会话、终止和媒体释放 | 不因界面隐藏误挂断，不接管消息队列 |
| [Web 平台](web-platform/spec.md) | 存储配额/生命周期、跨标签所有权、通知与推送、外观设置、PWA与更新 | 不用缓存清理规则处理密钥，不替浏览器承诺后台常驻 |

一次普通新消息发送的责任顺序：会话交互提供草稿 → 房间域提供当前能力、账户域提供身份/加密能力 → 消息发送域接管唯一快照 → SDK响应与同步结果回到消息发送域 → 会话交互展示其结果。编辑/反应/撤回/置顶则由会话关系服务持有操作及 SDK 结果，不进入普通消息队列。每个状态只有一个所有者，交叉规格通过链接引用，不复制规则或模型。

## 如何阅读

先看相应 `spec.md` 的 `### 1.0 设计图景`。它说明谁对什么对象做什么、成功/失败看到什么、随后去哪里；REQ、决策和内嵌语义只是图的投影。

- `spec.md`：目标行为与契约。
- `tools/`：本域自包含的结构审计、负例自测、屏障与验证状态说明。
- `issues/`：未闭合的核验或决策，不放未确认规则。
- `history/`：只读历史材料，不作为当前行为依据。
- 消息发送域另含内嵌旧代语义、生成快照与评审材料；旧代没有真实 Matrix 迹线，不计 strict pass。

原 `client-core` 聚合入口已撤下。它的旧架构讨论稿仅作历史材料保存；六域之间的职责变更先修改相应操作图，再同步引用、契约与评审。
